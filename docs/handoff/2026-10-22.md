## Merge mechanics (read before merging)

- **Merge in the order below, squash as usual.** Each PR's base is the PR before it.
- The repo has **"Automatically delete head branches" off**. After each merge, either delete the merged branch, so GitHub retargets the next PR to `main` automatically, or retarget it by hand with `gh pr edit <next> --base main`.
- After a squash merge, the next PR's diff on GitHub can show the previous PR's changes until it's retargeted or rebased. The merge itself stays clean, because the content is identical.
- **Every PR was gated at its own position in the stack:** `pnpm build` plus `pnpm verify` at that branch's tip. Each PR has a comment with its numbers. Rebase conflicts were all textual and are named in those comments: import lines, two CSS rules side by side, one test helper.
- **Dependabot #15 and #16** (dev-only; they fix all four security alerts, #109) touch the same lockfile as #18. Merge them **after** the stack and let Dependabot rebase itself.
- **One CLAUDE.md change outside #17:** #53 adds `src/data/buy-next.ts` to the ADR-008 row, because ADR-008's logic moved there. ADR-010 makes CLAUDE.md changes your call.
